# MySQL2PG 使用手册

> **MySQL2PG v3.4.0** · Go 1.24+ · Apache-2.0
>
> MySQL to PostgreSQL Migration Tool ——
> 高性能异构数据库全链路迁移工具

---

## 概述

**MySQL2PG** 是一款用 Go 语言开发的专业级数据库迁移工具，专注于将 MySQL 数据库无缝迁移到 PostgreSQL。它覆盖 DDL 表结构、数据、视图、索引、函数、用户、权限和数据校验的全链路转换，单二进制文件、零外部依赖，支持 Linux / macOS / Windows。

MySQL2PG 将传统 DTS 工具需要人工介入的适配、校验、结构兼容工作全部自动化，8 步流水线一键完成全量迁移，每一步均可独立开关控制。

## 安装

### 下载二进制

从 [GitHub Releases](https://github.com/xfg0218/MySQL2PG/releases) 下载对应平台的预编译二进制文件，赋予执行权限即可使用：

```bash
chmod +x mysql2pg
./mysql2pg -h
```

### 从源码构建

```bash
git clone https://github.com/xfg0218/MySQL2PG.git
cd MySQL2PG
make build
```

构建产物为当前目录下的 `mysql2pg` 单文件，无运行时依赖。

**系统要求**：最低 256MB 内存，无需安装 Go 运行时。

## 快速开始

3 步完成首次迁移。

### 第 1 步：创建配置文件

```yaml
# config.yml
mysql:
  host: localhost
  port: 3306
  username: root
  password: your_password
  database: mydb

postgresql:
  host: localhost
  port: 5432
  username: postgres
  password: your_password
  database: mydb

conversion:
  options:
    tableddl: true
    data: true
    view: true
    indexes: true
    functions: true
    users: true
    table_privileges: true
    validate_data: true
```

### 第 2 步：运行迁移

```bash
# 可选：迁移前评估，生成兼容性报告
./mysql2pg assess config.yml

# 执行迁移
./mysql2pg -c config.yml
```

### 第 3 步：查看报告

```bash
# 从转换日志生成 HTML 可视化报告
./mysql2pg report -l conversion.log

# 包含错误日志
./mysql2pg report -l conversion.log -e errors.log

# 自定义输出路径
./mysql2pg report -l conversion.log -o my-report.html
```

报告为单文件 HTML，深色终端风格，包含统计卡片、性能柱状图、表明细和数据不一致清单。

## 运行模式

MySQL2PG 提供 4 种运行模式，覆盖迁移全生命周期。

### test_only — 连接测试

仅测试数据库连接，不执行任何转换。响应时间 < 1 秒。

```yaml
mysql:
  test_only: true
postgresql:
  test_only: true
```

```bash
./mysql2pg -c config.yml
```

输出 MySQL 和 PostgreSQL 的版本信息，用于快速验证连接配置是否正确。

### assess — 迁移前评估

v3.4.0 新增。在正式迁移前运行，分析所有表、视图、函数、索引、用户和权限的兼容性，生成 HTML 评估报告。

```bash
./mysql2pg assess config.yml
```

评估报告包含：

- **总体评分**：0-100 兼容性评分
- **风险等级**：低 / 中 / 高
- **详细清单**：每个对象的不兼容问题和建议
- **统计概览**：表、视图、函数、索引、用户、权限的数量和 DDL 行数

评估模式只读不写，对源库和目标库均无副作用。

### 正常迁移

按配置文件中的 `conversion.options` 开关，依次执行 8 步转换流水线。

```bash
# 使用默认配置文件 config.yml
./mysql2pg

# 指定配置文件
./mysql2pg -c config.yml
./mysql2pg config.yml
```

### report — 生成 HTML 报告

从已有的转换日志生成可视化报告，不需要重新执行迁移。

```bash
./mysql2pg report -l conversion.log [-e errors.log] [-o output.html]
```

| 参数 | 说明 |
|------|------|
| `-l` | 转换日志文件路径（必需） |
| `-e` | 错误日志文件路径（可选） |
| `-o` | 输出 HTML 文件路径（可选，默认自动生成带时间戳的文件名） |

### 核心参数

#### 数据库连接

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `mysql.host` / `postgresql.host` | `localhost` | 数据库地址 |
| `mysql.port` / `postgresql.port` | `3306` / `5432` | 端口号 |
| `mysql.username` / `postgresql.username` | — | 用户名 |
| `mysql.password` / `postgresql.password` | — | 密码，支持环境变量注入 |
| `mysql.database` / `postgresql.database` | — | 数据库名 |
| `mysql.test_only` / `postgresql.test_only` | `false` | 仅测试连接 |
| `mysql.max_open_conns` | `100` | MySQL 连接池最大连接数 |
| `mysql.max_idle_conns` | `50` | MySQL 连接池最大空闲连接数 |
| `postgresql.max_conns` | `50` | PostgreSQL 连接池最大连接数 |
| `mysql.connection_params` | — | MySQL 连接参数，格式 `key=value&key=value` |
| `postgresql.pg_connection_params` | — | PostgreSQL 连接参数 |

#### 转换开关

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `conversion.options.tableddl` | `true` | 转换表结构 |
| `conversion.options.data` | `true` | 同步数据 |
| `conversion.options.view` | `true` | 转换视图 |
| `conversion.options.indexes` | `true` | 转换索引 |
| `conversion.options.functions` | `true` | 转换函数 |
| `conversion.options.users` | `true` | 转换用户 |
| `conversion.options.table_privileges` | `true` | 转换表权限 |
| `conversion.options.validate_data` | `true` | 同步后校验数据一致性 |

#### 同步策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `conversion.options.truncate_before_sync` | `false` | 同步前是否清空目标表 |
| `conversion.options.skip_existing_tables` | `true` | 目标表已存在时跳过 |
| `conversion.options.lowercase_columns` | `true` | 字段名转小写 |

#### 并发与批量

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `conversion.limits.concurrency` | `10` | 并发线程数 |
| `conversion.limits.max_rows_per_batch` | `50000` | 每批读取行数 |
| `conversion.limits.batch_insert_size` | `50000` | 每批插入行数 |
| `conversion.limits.bandwidth_mbps` | `100` | 网络带宽限制（Mbps） |

#### 表 / 视图 / 函数过滤

| 参数 | 说明 |
|------|------|
| `use_table_list` + `table_list` | 白名单模式，仅同步指定表 |
| `exclude_use_table_list` + `exclude_table_list` | 黑名单模式，跳过指定表 |
| `exclude_use_view_list` + `exclude_view_list` | 跳过指定视图 |
| `exclude_use_function_list` + `exclude_function_list` | 跳过指定函数 |

白名单和黑名单不能同时使用，同时设置时白名单优先。表名区分大小写，视图和函数名不区分大小写。

## 迁移流程详解

MySQL2PG 按以下 8 步顺序执行，每步可通过配置独立开关。

```
Step 0  连接测试（test_only 模式时到此结束）
  │
Step 1  读取 MySQL 表定义
  │     支持白名单 / 黑名单过滤
  │
Step 2  转换表结构（tableddl: true）
  │     字段类型智能映射，MPP 分布键自动添加
  │
Step 3  转换视图（view: true）
  │     反引号替换、LIMIT 语法转换、函数替换
  │
Step 4  同步数据（data: true）
  │     并发批量插入，自动禁用外键和索引提升性能
  │
Step 5  转换索引（indexes: true）
  │     主键 / 唯一 / 普通 / 全文索引自动重建
  │
Step 6  转换函数（functions: true）
  │     50+ MySQL 函数自动映射为 PostgreSQL 等效函数
  │
Step 7  转换用户（users: true）
  │     MySQL 用户 → PostgreSQL Role，保留密码哈希
  │
Step 8  转换权限 + 数据校验
        表级 GRANT 映射，行数一致性校验
        生成不一致表清单
```

每个阶段的转换结果实时输出到控制台和日志文件，进度更新频率 1 次/秒。

## SQL 转换参考

### 类型映射

覆盖 MySQL 全部字段类型，映射准确率 100%。以下为关键映射：

| MySQL | PostgreSQL | 说明 |
|-------|-----------|------|
| `INT AUTO_INCREMENT` | `SERIAL` | 自增整数 |
| `BIGINT AUTO_INCREMENT` | `BIGSERIAL` | 自增大整数 |
| `TINYINT(1)` | `BOOLEAN` | 布尔值 |
| `DATETIME` / `DATETIME(n)` | `TIMESTAMP` / `TIMESTAMP(n)` | 保留精度 |
| `JSON` | `JSONB` | 默认映射为二进制 JSON |
| `BLOB` / `LONGBLOB` / `BINARY` | `BYTEA` | 二进制类型统一 |
| `ENUM('a','b')` | `VARCHAR(20) CHECK (col IN ('a','b'))` | 值域约束保留 |
| `SET` | `TEXT[]` | 集合转数组 |
| `GEOMETRY` | `GEOMETRY` | 需 PostGIS 扩展 |
| `DOUBLE` | `DOUBLE PRECISION` | 双精度浮点 |
| `UNSIGNED` 类型 | 自动升级位宽 | PostgreSQL 无无符号类型 |

完整 40+ 类型映射表见 [docs/MYSQL2PG.md](MYSQL2PG.md)。

### 函数转换

支持 50+ MySQL 内置函数自动映射，准确率 90%+。以下为常用映射：

| MySQL | PostgreSQL | 类别 |
|-------|-----------|------|
| `IFNULL(x, y)` | `COALESCE(x, y)` | 空值处理 |
| `IF(cond, a, b)` | `CASE WHEN cond THEN a ELSE b END` | 条件判断 |
| `GROUP_CONCAT(x)` | `STRING_AGG(CAST(x AS text), ',')` | 聚合 |
| `DATE_FORMAT(dt, fmt)` | `TO_CHAR(dt, fmt)` | 日期格式 |
| `STR_TO_DATE(s, fmt)` | `TO_DATE(s, fmt)` | 日期解析 |
| `DATEDIFF(d1, d2)` | `date_part('day', d1 - d2)` | 日期差 |
| `JSON_EXTRACT(doc, path)` | `doc -> 'key'` | JSON 提取 |
| `JSON_EXTRACT(doc, path)` | `doc ->> 'key'` | JSON 文本值 |
| `REGEXP_LIKE(expr, pat)` | `expr ~ pat` | 正则匹配 |
| `REGEXP_REPLACE(s, p, r)` | `regexp_replace(s, p, r)` | 正则替换 |
| `CONCAT(a, b)` | `a \|\| b` | 字符串拼接 |
| `UNIX_TIMESTAMP()` | `extract(epoch from now())` | 时间戳 |
| `UUID()` | `uuid_generate_v4()` | UUID 生成 |

完整函数转换表（含 JSON / 时间 / 加密 / 网络函数族）见 [docs/MYSQL2PG.md](MYSQL2PG.md)。

### 视图转换规则

| 规则 | MySQL | PostgreSQL |
|------|-------|-----------|
| 标识符 | 反引号 `` `col` `` | 双引号 `"col"` |
| 分页 | `LIMIT 10, 20` | `LIMIT 20 OFFSET 10` |
| 标准分页 | `LIMIT 100` | `FETCH FIRST 100 ROWS ONLY` |
| 函数替换 | 视图内函数自动转换 | 同函数转换表 |

支持批量转换（每批 10 个）。

### 用户与权限映射

**用户转换**：

```sql
-- MySQL
CREATE USER 'app_user'@'%' IDENTIFIED BY 'SecurePass123';

-- PostgreSQL
CREATE ROLE app_user WITH LOGIN PASSWORD 'SecurePass123';
```

**权限转换**：

```sql
-- MySQL
GRANT SELECT, INSERT, UPDATE ON mydb.users TO 'app_user'@'%';

-- PostgreSQL
GRANT SELECT, INSERT, UPDATE ON TABLE users TO app_user;
```

密码哈希保留，表级 GRANT 完整映射，准确率 100%。

## 常用场景

### 全量迁移

清空目标表后全量同步，确保数据完全一致。

```yaml
conversion:
  options:
    truncate_before_sync: true
    validate_data: true
    concurrency: 20
```

校验失败时工具会中断执行并返回错误。

### 仅迁移指定表

白名单模式，只同步 `table_list` 中的表。

```yaml
conversion:
  options:
    use_table_list: true
    table_list: [users, orders, products]
```

### 排除特定表

黑名单模式，跳过 `exclude_table_list` 中的表。

```yaml
conversion:
  options:
    exclude_use_table_list: true
    exclude_table_list: [tmp_log, cache_data]
```

### 保留已有数据追加同步

不清空目标表，新数据追加写入。

```yaml
conversion:
  options:
    truncate_before_sync: false
    validate_data: true
```

校验失败时不中断执行，最终输出不一致表清单。

### MPP 分布式迁移

自动检测 Greenplum / YugabyteDB，添加 `DISTRIBUTED BY` 分布键。

```yaml
conversion:
  mpp:
    enabled: true
    database: auto  # 或 greenplum / yugabyte
```

启用后自动使用主键列作为分布键，Greenplum 上跳过冗余 UNIQUE INDEX。

### 跳过复杂视图或函数

排除不需要迁移或转换困难的视图和函数。

```yaml
conversion:
  options:
    exclude_use_view_list: true
    exclude_view_list: [v_complex_report, v_temp_stats]
    exclude_use_function_list: true
    exclude_function_list: [func_deprecated, func_mysql_only]
```

### 性能调优

大表（亿级行）场景推荐配置：

```yaml
conversion:
  limits:
    concurrency: 20          # 根据 CPU 核数调整
    max_rows_per_batch: 10000
    batch_insert_size: 10000
    bandwidth_mbps: 200
```

建议先同步数据再创建索引（将 `indexes` 设为 `false`，数据同步完成后单独开启索引转换），以提升写入性能。

## 数据安全

**凭证安全** — 配置文件本地存储，支持环境变量注入密码，凭证不上传任何外部服务。

**传输加密** — 支持 SSL/TLS 加密连接 MySQL 和 PostgreSQL，数据传输全程加密。

**源库零修改** — 评估模式只读不写。正式迁移采用"先转换后写入"策略，源库不受任何影响。读取阶段使用一致性快照，不阻塞源库正常读写。

## 故障排查

### 连接失败

```bash
# 先用 test_only 模式验证连接
# 在配置文件中设置 mysql.test_only: true 和 postgresql.test_only: true
./mysql2pg -c config.yml
```

检查项：网络连通性、端口是否开放、用户名密码是否正确、数据库是否存在。

### 数据校验不一致

当 `truncate_before_sync: false` 时，校验不一致不会中断执行。转换完成后会输出不一致表清单：

```
+------------------+----------------+------------------+
| 表名             | MySQL数据量    | PostgreSQL数据量 |
+------------------+----------------+------------------+
| user             | 327680         | 655360           |
+------------------+----------------+------------------+
```

常见原因：迁移期间源库有新写入、触发器导致额外行、`truncate_before_sync` 未开启导致数据叠加。

### 视图或函数转换失败

使用排除列表跳过转换失败的对象，后续手动处理：

```yaml
exclude_use_view_list: true
exclude_view_list: [v_failed_view]
```

查看 `errors.log` 获取详细错误信息。

### 大表迁移速度慢

- 提高 `concurrency`（建议 CPU 核数的 2 倍）
- 增大 `max_rows_per_batch` 和 `batch_insert_size`
- 先同步数据后创建索引
- 检查网络带宽是否成为瓶颈

### GEOMETRY 类型报错

目标库需安装 PostGIS 扩展：

```sql
CREATE EXTENSION postgis;
```

### 密码认证失败

PostgreSQL 14+ 默认使用 `scram-sha-256` 加密。如需兼容旧客户端，可在配置中指定：

```yaml
postgresql:
  password_encryption: md5  # 或 scram-sha-256 / auto
```
